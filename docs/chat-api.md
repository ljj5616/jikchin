# 방 채팅 API

방 생성·참여 API로 참여한 방에서 사용하는 텍스트 채팅입니다. `roomId`는 모집방 ID이며 `chatThreadId`와 구분합니다. 경기 날짜가 지난 방에서도 현재 참여자는 채팅할 수 있습니다.

## 인증과 접근 범위

- REST는 기존과 같이 `Authorization: Bearer {accessToken}`이 필요합니다.
- WebSocket 주소는 `ws://{host}/ws/chat`이며 HTTPS 환경에서는 `wss://`를 사용합니다. SockJS는 사용하지 않습니다.
- WebSocket HTTP 연결 후 **STOMP CONNECT 프레임**에 `Authorization: Bearer {accessToken}`을 넣습니다. URL 쿼리에 토큰을 넣지 않습니다. HTTP 연결 자체가 열려도 CONNECT 인증 전에는 채팅할 수 없습니다.
- 프로필 등록을 완료한 활성 회원의 액세스 토큰만 허용합니다. 온보딩 토큰, 비활성 회원, 유효하지 않거나 만료된 토큰은 거절합니다.
- 전송·조회·구독은 현재 참여자만 가능합니다. 신규 참여 시 마지막 메시지 ID를 기록해 그 이후 메시지만 공개합니다. 입장과 전송은 같은 방 잠금을 사용하므로 동시 요청에도 공개 범위가 유지됩니다.
- 퇴장 시 이전 구독으로의 수신을 차단합니다. 재참여해도 이전 구독은 유효해지지 않으므로 구독을 해제한 뒤 새로 구독해야 합니다. 재참여 이전 메시지는 조회할 수 없습니다.
- 연결 중에도 전송·수신 시 토큰 만료와 현재 참여 권한을 다시 검사합니다. 토큰 갱신 후 새 토큰으로 연결하고 재구독하세요. 기존 로그아웃 정책처럼 이미 발급된 액세스 토큰은 만료 전까지 유효합니다.

## 메시지 전송

STOMP `SEND /app/rooms/{roomId}/messages` 또는 REST `POST /api/rooms/{roomId}/messages`에 동일한 JSON을 전달합니다. `content-type`은 `application/json`입니다.

```json
{
  "body": "안녕하세요! 같이 직관해요 🏟️",
  "clientMessageId": "8e85e9b4-786b-4480-ae42-af43ce467203"
}
```

- `body`: 공백만으로 이루어지지 않은 1~2000자 문자열입니다. 줄바꿈과 앞뒤 공백을 보존합니다. 길이는 Java 문자열 기준이며 이모지는 두 글자로 계산될 수 있습니다.
- `clientMessageId`: 앱이 메시지마다 생성하는 UUID 문자열입니다. 대소문자는 소문자로 정규화합니다. 전송 결과를 받지 못해 재시도할 때 **동일한 ID와 본문**을 사용합니다.
- 같은 방·발신자·UUID의 재요청은 기존 메시지를 반환하며 새 저장·방송을 하지 않습니다. 같은 UUID로 내용을 바꾸거나 재참여 이전 메시지를 재전송하면 `409`입니다.
- 발신자와 전송 시각은 서버가 정합니다. 클라이언트에서 발신자 ID를 지정하지 않습니다.
- REST 응답은 최초 전송과 재시도 모두 `200 OK`입니다.

## 실시간 수신과 전송 확인

STOMP `SUBSCRIBE` 대상은 다음과 같습니다.

| 목적 | 구독 경로 |
| --- | --- |
| 방 메시지 | `/topic/rooms/{roomId}/messages` |
| 해당 연결의 전송 성공 확인 | `/user/queue/chat-acks` |
| 해당 연결의 요청 오류 | `/user/queue/chat-errors` |

방 메시지는 DB 커밋이 완료된 뒤 발신자를 포함한 해당 방의 구독자에게 전달됩니다. 성공 확인은 STOMP로 전송한 연결에만 전달되며, 중복 재시도에도 기존 메시지로 응답합니다. 성공 확인은 서버 저장을 의미하며 상대방의 읽음을 의미하지 않습니다. HTTP 전송은 HTTP 응답으로 성공을 확인합니다.

방 메시지, 전송 성공 확인, REST 전송 응답의 형식은 같습니다.

```json
{
  "id": 125,
  "roomId": 10,
  "chatThreadId": 12,
  "senderId": 7,
  "senderNickname": "직관친구",
  "senderAvatarUrl": "https://assets.example.com/avatars/defaults/default1.jpg",
  "type": "TEXT",
  "body": "안녕하세요! 같이 직관해요 🏟️",
  "clientMessageId": "8e85e9b4-786b-4480-ae42-af43ce467203",
  "createdAt": "2026-11-05T19:30:00.123456"
}
```

`createdAt`은 기존 서버 모델과 같은 서버 현지 시각의 `LocalDateTime`입니다. 프로필 없는 기존 회원은 닉네임이 null이고 기본 사진을 사용합니다. 현재 프로필을 기준으로 표시하며 전송 당시 프로필의 스냅샷은 보관하지 않습니다. 이전에 DB에 저장한 메시지는 `clientMessageId`가 null일 수 있습니다.

서버 저장 순서는 `id` 오름차순입니다. 서로 다른 사용자나 연결에서 동시에 보낸 메시지의 네트워크 도착 순서는 달라질 수 있으므로 앱은 `id`로 정렬하고 중복을 제거합니다. 자신의 방 메시지와 성공 확인을 모두 받았을 때도 하나만 표시합니다.

와일드카드, 다른 사용자의 개인 큐, 내부 `/queue/...` 직접 구독, `/topic/...` 직접 전송은 거절합니다.

## 대화 조회

`GET /api/rooms/{roomId}/messages?size=50&beforeId=125`

- `size`: 기본 50, 1~100입니다.
- `beforeId`: 생략하면 최근 대화, 지정하면 해당 ID 미만의 과거 대화입니다. 양수여야 합니다.
- 한 페이지 안의 메시지는 오래된 것부터 정렬합니다. 참여 시점보다 이전 대화와 다른 방의 메시지는 포함하지 않습니다.

```json
{
  "messages": [],
  "hasMore": false,
  "nextBeforeId": null
}
```

`hasMore=true`이면 `nextBeforeId`를 다음 요청의 `beforeId`에 넣어 이전 페이지를 조회합니다.

앱 연결 순서는 CONNECT → 성공 확인·오류·방 메시지 구독 → 최근 대화 조회입니다. 구독한 실시간 메시지를 잠시 보관하고 조회 결과와 ID로 병합하세요. 연결이 끊겼을 때 놓친 메시지도 같은 방식으로 조회합니다. 최근 페이지에 기존 마지막 수신 메시지가 없다면 과거 페이지를 이어서 조회해 공백을 채웁니다. 이 서버의 내장 브로커는 STOMP ACK·RECEIPT와 오프라인 전송 큐를 제공하지 않으며 영구 저장된 대화가 복구의 기준입니다.

## 오류

- REST: 인증 없음·만료 `401`, 온보딩·비참여 `403`, 없는 방 `404`, UUID 충돌 `409`, 잘못된 입력 `400`입니다.
- CONNECT·SUBSCRIBE·허용되지 않은 SEND 등 프로토콜/권한 오류: STOMP `ERROR`의 JSON 본문에 `status`, `message`를 넣고 연결을 종료합니다.
- 메시지 본문 검증·저장 요청 오류: `/user/queue/chat-errors`로 `{"status":400,"message":"..."}`를 전달합니다. 이 큐는 전송 전에 구독해야 합니다.
- 액세스 토큰이 만료되면 기존 REST 갱신 API로 새 토큰을 발급받고 재접속합니다. 만료된 연결로는 새 메시지가 전달되지 않습니다. 서버 heartbeat는 10초이며 클라이언트도 heartbeat를 협상하는 것이 좋습니다.

## 실행과 범위

본인이 차단한 사용자가 보낸 메시지는 내역 조회와 새 실시간 수신의 `senderNickname`에 `(차단)`을 붙입니다. 표시는 수신자별로 적용하므로 상대나 다른 참여자에게 노출되지 않으며 본문은 유지합니다. 차단·해제 후 새 수신과 다시 조회한 내역에는 현재 상태를 반영합니다. 이미 수신한 메시지는 앱이 내역을 다시 조회해야 갱신됩니다. 차단은 기존 방 참여와 구독을 종료하지 않습니다. 차단 API와 방 입장 제한은 README의 사용자 차단 절을 확인하세요.

서버 시작 시 Flyway V7을 적용합니다. 기존 참여자의 공개 범위는 저장된 `joined_at` 이전 메시지의 최대 ID로 초기화합니다. 기존 메시지를 삭제하지 않습니다. 마지막 참여자의 퇴장에 따른 방·메시지 삭제 정책도 유지합니다.

추가 외부 서비스 없이 **단일 애플리케이션 인스턴스**에서 동작합니다. 여러 서버로 확장할 때는 공유 브로커와 서버 간 구독·권한 동기화를 추가해야 합니다. 저장과 실시간 방송 사이에 서버가 종료된 경우에는 재접속 대화 조회로 복구합니다. 이번 범위는 그룹 텍스트 송수신이며 이미지·파일, 읽음/안 읽은 수, 푸시 알림, 입력 중 표시와 1:1 채팅 API는 포함하지 않습니다.

```powershell
.\gradlew.bat test
```

테스트에는 실제 WebSocket 연결을 사용한 방 메시지·성공 확인, 비참여자 접근 거절, 퇴장/재참여 구독 차단, 롤백 시 방송 방지 및 동시 재전송 검증이 포함됩니다. MySQL 스키마 검증은 README의 `mysqlTest`를 실행합니다.
