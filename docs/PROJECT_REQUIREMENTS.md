# 직친 프로젝트 기능 기준

이 문서는 사용자가 설명한 현재 프로젝트 방향을 기록합니다. 구현 완료 여부와는 별개이며, 이후 사용자가 기능을 변경하거나 추가하면 그에 맞춰 갱신합니다.

## 서비스 대상

- 성인만 사용할 수 있는 스포츠 직관 동행 앱입니다.

## 가입 및 프로필 완성

1. 소셜 로그인으로 회원가입합니다.
2. 이름, 나이, 성별은 PASS 인증으로 진행하거나, 성인임을 인증할 수 있는 방식을 사용합니다. 구체적인 인증 방식은 확정되지 않았습니다.
3. 닉네임을 설정하고 중복 여부를 확인하며, 프로필 사진과 한 줄 소개를 작성합니다.
4. KBO와 K리그 응원팀을 각각 설정할 수 있습니다. 응원팀이 없으면 각 선택을 건너뛸 수 있습니다.

## 직관 방과 채팅

- 사용자는 방을 생성하거나 방 목록을 보고 원하는 방에 참여할 수 있습니다.
- 방 상세 정보와 방장·참여자의 닉네임 및 프로필 사진을 조회할 수 있습니다.
- 방 생성 시 방 제목, 날짜, 어느 팀 대 어느 팀의 경기인지와 경기장, 방장을 포함한 최대 인원 등을 정합니다.
- 방을 생성한 사용자는 방장입니다.
- 방은 채팅방 형식입니다.
- 한 사용자가 여러 방에 동시에 참여할 수 있고, 여러 방을 생성할 수도 있습니다.
- 참여자는 방을 나갈 수 있습니다. 방장이 나가면 남아 있는 참여자 중 가장 먼저 입장한 사람에게 방장을 자동 위임합니다. 이미 나간 사람은 제외합니다.
- 방장 혼자 있는 방에서 방장이 나가면 방은 자동으로 삭제됩니다.

## 마이페이지

- 닉네임, 프로필 사진, 한 줄 소개, 응원팀 등을 확인하고 수정할 수 있습니다.
- 본인이 차단한 사용자 목록을 확인하고 차단을 해제할 수 있습니다. 목록에는 사용자 ID, `닉네임(차단)`, 프로필 사진, 차단 시각을 표시하며 최근 차단한 순서로 정렬합니다.

## 회원 탈퇴

- 프로필 등록을 완료한 회원은 마이페이지에서 본인 계정을 탈퇴할 수 있습니다. API는 `DELETE /users/me`이며 성공 시 `204`를 반환합니다.
- 탈퇴 시 프로필, 직관 기록·이미지 연결, 본인과 관련된 차단 관계와 모든 갱신 세션을 삭제하고 소셜 로그인 식별자를 제거합니다. 기존 액세스 토큰과 WebSocket 채팅 이용도 차단합니다.
- 참여 중인 모든 방에서 퇴장하며 방장 위임과 마지막 참여자의 방 삭제는 기존 퇴장 규칙을 따릅니다. 남아 있는 대화의 발신자는 `탈퇴한 회원`과 기본 사진으로 표시합니다.
- 신고 내역·신고 당시 대상 정보, 포인트 이력, 공유 대화와 채팅 미디어는 남겨 두고 익명화한 회원 행으로 참조를 유지합니다. 프로필·직관 사진의 S3 파일 삭제와 소셜 제공자 연결 해제는 별도 처리 대상입니다.
- 같은 소셜 계정의 재가입은 새 회원 ID와 새 프로필로 시작하며 기존 데이터를 복원하지 않습니다. 이전 닉네임은 다시 사용할 수 있습니다.
- 방 생성·참여와의 경합으로 정리할 방이 바뀌면 변경 없이 `409`를 반환하므로 다시 요청합니다. 성공 후 앱은 로컬 회원 정보와 토큰을 지우고 로그인 화면으로 이동합니다.

## 사용자 차단

- 프로필 등록을 완료한 사용자는 다른 사용자를 차단하거나 차단을 해제할 수 있습니다. 본인은 차단할 수 없습니다.
- 차단한 사용자 이름은 차단한 본인에게만 `닉네임(차단)`으로 표시합니다. 실제 닉네임은 변경하지 않으며 상대나 다른 사용자에게 차단 표시를 노출하지 않습니다.
- 차단 표시는 방 참여자 목록, 기존 채팅 내역 조회, 새 실시간 채팅 메시지의 발신자 닉네임과 마이페이지 차단 목록에 적용합니다. 차단 해제 후 다시 조회하거나 새로 받는 메시지에는 원래 닉네임을 표시합니다. 앱이 이미 표시한 목록과 메시지는 다시 조회해야 갱신됩니다.
- 한쪽이라도 차단한 관계라면 서로가 만든 방에 새로 참여할 수 없습니다. 여기서 만든 사람은 현재 방장이 아닌 최초 방 생성자이며, 방장이 자동 위임되어도 입장 제한 기준은 유지합니다.
- 차단은 기존 참여자를 자동으로 퇴장시키지 않습니다. 이미 참여한 방과 채팅은 유지하며, 퇴장 후 다시 참여할 때는 입장 제한을 적용합니다. 기존 참여자의 중복 참여 요청은 기존처럼 성공합니다.
- 방 목록·상세·참여자 미리보기는 유지합니다. 제3자가 만든 방에서는 차단 관계인 사용자도 함께 참여할 수 있으며 메시지 본문은 숨기지 않습니다.
- 차단 해제는 본인이 설정한 차단만 삭제합니다. 상대방이 설정한 차단이 남아 있으면 서로 만든 방의 입장 제한도 유지합니다.
- 차단·해제를 반복 요청해도 중복 데이터나 오류 없이 처리하며, 차단한 사용자 목록은 본인만 조회할 수 있습니다.

## 사용자 프로필 조회

- 사용자 또는 방 참여자를 누르면 해당 사용자의 프로필을 표시합니다. 닉네임, 프로필 사진, 한 줄 소개, 응원팀과 본인의 차단 여부를 조회할 수 있습니다.
- 상대 프로필에 신고하기 버튼을 배치합니다. 본인 프로필에는 본인 신고 버튼을 표시하지 않습니다.
- 차단한 상대의 프로필도 조회·신고할 수 있으며 닉네임은 기존 차단 규칙에 따라 `닉네임(차단)`으로 표시합니다.

## 유저 신고

1. 상대 프로필의 신고하기를 누르면 유저 신고 사유 목록을 표시합니다.
2. 사유 하나를 선택한 후 상세 내용을 입력하는 화면으로 이동합니다.
3. 상세 내용은 필수이며 최대 2000자입니다. 앞뒤 공백을 제거한 결과가 비어 있으면 제출할 수 없습니다.
4. 제출하면 서버가 신고를 접수하고 관리자 검토 대기 상태로 보관합니다.

유저 신고 사유는 다음과 같습니다.

- 욕설·비방·혐오 표현
- 괴롭힘·위협·스토킹
- 음란·성적 불쾌감 유발
- 광고·도배
- 사기·금전 요구
- 개인정보 노출·침해
- 타인 사칭
- 부적절한 닉네임·프로필 사진
- 기타

## 방 신고

- 방 목록의 각 방에 있는 더보기(점 세 개 등) 메뉴에서 신고하기를 선택할 수 있습니다. 방에 참여하기 전에도 신고할 수 있습니다.
- 방에 참여한 후에는 채팅방 우측 상단 메뉴에 참여자 목록을 표시하고, 아래쪽에 신고하기와 나가기 버튼을 배치합니다. 나가기는 기존 방 나가기 기능을 사용합니다.
- 신고하기를 누르면 방 신고 사유 목록을 표시하고 사유 하나를 선택한 후 상세 내용을 입력합니다. 상세 내용은 선택 사항이며 생략·빈칸을 허용하고 최대 2000자입니다.
- 제출하면 유저 신고와 같이 관리자 검토 대기 상태로 보관합니다. 본인이 최초 생성한 방은 신고할 수 없습니다.

방 신고 사유는 다음과 같습니다.

- 욕설·비방·혐오 표현
- 음란·성적 불쾌감 유발
- 광고·도배
- 사기·금전 요구
- 개인정보 노출·침해
- 허위 경기·모집 정보
- 불법 거래·활동 유도
- 기타

## 신고 접수와 관리자 연동

- 신고 사유 목록과 기능 활성화 여부는 서버에서 조회합니다. 프로필 등록을 완료한 로그인 사용자만 사유 조회와 제출을 할 수 있습니다.
- 신고에는 인증된 신고자, 유저/방 구분, 대상 ID, 선택한 사유, 상세 내용, 접수 시각, 처리 상태와 신고 당시 대상 정보를 저장합니다. 최초 상태는 `PENDING`(검토 대기)입니다.
- 신고 대상의 닉네임이나 방 정보가 바뀌거나 방이 삭제되어도 신고 당시 정보와 접수 기록은 유지합니다.
- 신고 제출만으로 상대를 차단·정지하거나 방 참여자를 퇴장시키지 않습니다. 신고 여부와 상세 내용은 대상이나 다른 일반 사용자에게 공개하지 않습니다.
- 네트워크 재전송은 선택 사항인 동일한 `clientReportId`(UUID)로 중복 접수를 방지할 수 있습니다. 다른 사건을 신고할 때는 새 ID를 사용합니다.
- 관리자용 웹 페이지가 없어도 신고를 DB에 접수할 수 있습니다. 이후 관리자 인증과 신고 조회·처리 API 및 웹 페이지를 연결해 쌓인 신고를 검토합니다. 현재 단계에서는 외부 웹으로 전송하지 않고 DB에 보관합니다.
- 신고 접수는 기본 활성화(`REPORTS_ENABLED=true`)합니다. 설정을 `false`로 변경하고 서버를 재시작하면 접수를 중단하며, 앱은 서버가 반환한 `enabled=false`에 따라 신고 진입 버튼을 숨기거나 비활성화합니다. 접수 중단 중에도 기존 기록은 유지합니다.
